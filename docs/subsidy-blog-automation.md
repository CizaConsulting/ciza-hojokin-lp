# 補助金ブログ自動化

## 目的

補助金・支援制度の公式情報を定期的に確認し、重要な更新があったときだけ解説記事の下書きを作る。

記事作成までは自動化するが、当初は人が内容を確認し、Notionで「承認」にした記事だけ公開する。

## 記事は2系統に分ける

### 1. 実務解説記事

川原拓馬の支援経験、相談内容、判断基準をもとに作る。

例:

- 補助金申請前に設備を発注してよいか
- 補助金はいつ入金されるのか
- 赤字企業でも申請できるか
- 補助金と融資をどう組み合わせるか
- 補助金を使わない方がよい場合

流れ:

1. Notionの会議・相談ログ、判断ライブラリから素材を取得
2. 既存記事と重ならないテーマを1本選ぶ
3. 記事案をNotionの記事ドラフトDBへ「要レビュー」で保存
4. 人が確認・修正し「承認」に変更
5. 承認済みの記事を1本だけ公開
6. ビルドと公開に成功した後だけ「公開済」に変更

### 2. 最新情報の記事

官公庁や補助金事務局の公式ページを確認し、前回から重要な変更があった場合だけ記事案を作る。

流れ:

1. 監視対象URLを取得
2. 本文または更新情報の差分を前回取得分と比較
3. 重要な変更かどうかを判定
4. 公式URLと確認日時を付けて記事案を作成
5. Notionの記事ドラフトDBへ「要確認」で保存
6. 人が公式資料と記事案を照合
7. 「承認」にした記事だけ公開

## 初期の監視対象

- 中小企業庁
- 経済産業省
- ミラサポplus
- J-Net21
- 各補助金の公式事務局
- 大阪府・兵庫県など、主な対象地域の公式ページ

監視対象は `config/subsidy-sources.json` で管理する。

## 記事を作る更新

- 新しい公募の開始
- 締切や公募期間の変更
- 公募要領、交付規程、公式FAQの更新
- 対象者、補助率、補助上限、対象経費の変更
- 発注・契約可能時期など申請実務に影響する変更
- 新しい採択結果や次回公募予定の公表

次の変更だけでは原則として記事を作らない。

- レイアウトだけの変更
- 表記修正のみ
- 内容に影響しないPDF差し替え
- 同じ情報の再掲

## 安全ルール

- 公式URLがない記事案は作らない
- 取得日時と情報確認日を必ず保存する
- 日付、補助率、補助上限、対象者、対象経費は推測しない
- PDFや公式ページに書かれていない説明を事実として書かない
- 前回との差分が判定できない場合は「要確認」として止める
- 公募要領や公式FAQに矛盾がある場合は公開しない
- 1回の実行で作る記事案は最大1本
- 当初は完全自動公開しない
- 既存記事と同じテーマの場合は、新記事ではなく更新候補として保存する

## 最新情報記事の基本構成

1. 何が発表・変更されたか
2. いつから変わるか
3. どの企業に関係するか
4. 前回から何が変わったか
5. 申請を考えている企業が今すること
6. 注意点
7. 公式情報
8. 情報確認日

## 既存記事の更新方針

- 制度の基本解説は既存記事を更新する
- 大きな制度変更は新しい記事を作る
- 締切延長など短い情報は既存記事の更新履歴に追加する
- 終了した制度は冒頭に「現在は受付終了」と表示する
- 公募回、公開日、更新日、情報確認日を表示する

## Notionの記事ドラフトDBに必要な項目

必須:

- 記事タイトル
- ステータス: 要レビュー / 要確認 / 承認 / 公開済 / 見送り
- 記事種別: 実務解説 / 最新情報 / 既存記事更新
- スラッグ
- 本文

推奨:

- 公式情報URL
- 公式資料名
- 情報確認日
- 前回取得日
- 変更内容
- 対象制度
- 狙うキーワード
- 元素材URL
- 公開日
- 公開URL

## 実行頻度

- 公式情報確認: 平日1回
- 実務解説記事案: 週1回
- 承認済み記事の公開: 週1〜2回
- 既存記事の情報鮮度確認: 週1回

更新がない日は記事を作らない。

## 実装順序

1. 既存の経営管理ブログ公開処理を補助金サイトへ移植
2. Notionの記事ドラフトDBを共通または補助金専用で接続
3. 監視対象URLの取得と差分保存
4. 重要変更の抽出
5. 最新情報の記事案作成
6. 既存記事更新候補の抽出
7. 公開後チェックを追加

## 公開後チェック

- Astroのビルドが成功している
- sitemapに記事URLが含まれる
- ブログ一覧から記事へリンクされている
- canonicalが本番URLと一致する
- noindexが付いていない
- 公式情報URLが記事内にある
- 情報確認日が表示されている
