# 補助金ブログ自動化

## 基本方針

記事案の作成までは自動化するが、公開は人が確認した記事だけにする。

Notionの共通記事DBで、次のステータスを使用する。

- 要レビュー
- 修正依頼
- 承認
- 公開済
- 見送り

公開処理は、`サイト＝補助金`かつ`ステータス＝承認`の記事だけを対象にする。

## 記事は2系統

### 1. 実務解説記事

川原拓馬の補助金相談・支援経験、判断ライブラリ、公式情報を組み合わせて作る。

- 毎週水曜 10:00（日本時間）に記事案を1本作成
- 会議・相談ログのうち、`補助金`タグが付いた未使用の素材を選ぶ
- 公式情報源を必ず1つ選ぶ
- `サイト＝補助金`
- `記事種別＝実務解説`
- `ステータス＝要レビュー`
- 出典名、出典URL、情報確認日をNotionへ保存

### 2. 制度更新記事

官公庁や補助金事務局の公式ページを平日に確認し、重要な変更があった場合だけ記事案を作る。

- 平日 09:30（日本時間）に公式ページを確認
- 前回取得時の内容と比較
- レイアウト変更や表記修正だけなら記事を作らない
- 公募開始、締切変更、公募要領・FAQの重要変更、対象条件の変更、採択発表などを記事候補とする
- 1回の実行で作る記事案は最大1本
- 既存記事へ追記すべき場合は`記事種別＝既存記事更新`にする
- 新規記事の場合は`記事種別＝制度更新`にする

## 初期の監視対象

監視先は `config/subsidy-sources.json` で管理する。

現在の対象:

- 中小企業庁「補助金公募情報」
- 新事業進出・ものづくり商業サービス補助金 公式サイト
- 中小企業省力化投資補助金 公式サイト
- 事業承継・M&A補助金 公式サイト
- 中小企業庁「デジタル・IT化支援」
- 中小企業庁「補助金採択結果」

情報源を追加・停止する場合は、設定ファイルのURLと`enabled`を変更する。

## Notion共通記事DB

経営管理ブログと同じDBを使用する。

### 必須項目

- `タイトル`（title）
- `サイト`（select）
  - 経営管理
  - 補助金
- `記事種別`（select）
  - 実務解説
  - 制度更新
  - 既存記事更新
- `ステータス`（selectまたはstatus）
  - 要レビュー
  - 修正依頼
  - 承認
  - 公開済
  - 見送り
- `スラッグ`（rich_text）
- `出典名`（rich_text）
- `出典URL`（url）
- `情報確認日`（date）

### 使用する項目

- `対象制度`
- `変更内容`
- `元素材`
- `元素材URL`
- `狙うキーワード`
- `既存記事URL`
- `レビューコメント`
- `生成日`
- `公開日`
- `公開URL`

## 公開処理

平日 09:00（日本時間）に次の条件を満たす記事を1本だけ処理する。

```text
サイト＝補助金
かつ
ステータス＝承認
かつ
出典URLあり
かつ
情報確認日あり
```

処理の流れ:

1. Notionから最も古い承認記事を取得
2. 投稿先が補助金であることを再確認
3. 出典名、出典URL、情報確認日、スラッグを確認
4. Astroの記事ファイルを作成または更新
5. `npm run build`を実行
6. GitHubへのpushに成功
7. Notionを`公開済`へ変更
8. 公開日と公開URLを記録

## 投稿先の取り違え防止

- Notionの`サイト`で補助金記事だけを抽出
- GitHubリポジトリを`ciza-hojokin-lp`に固定
- 公開先ドメインを`hojokin.ciza.co.jp`に固定
- ドメインが一致しない場合は処理を停止
- 1回の実行で公開する記事は最大1本

## 出典の扱い

全記事に出典を必須とする。

公開記事には次を自動で追加する。

- 出典名
- 公式ページへのリンク
- 情報確認日
- 最新の公式資料を確認するよう促す注意書き

出典名、出典URL、情報確認日が1つでも欠けている場合は公開しない。

## 既存記事更新

`記事種別＝既存記事更新`の場合:

- `既存記事URL`または`スラッグ`から更新対象を決める
- 既存ファイルが見つからない場合は処理を停止
- 初回公開日は維持する
- `updatedAt`を追加・更新する
- 出典と情報確認日を最新の内容へ差し替える

## 安全ルール

- 日付、締切、補助率、補助上限、対象者、対象経費を推測しない
- 公式ページにない説明を事実として書かない
- 公式URLがない記事案は作らない
- 重要でない変更では記事を作らない
- 同じ更新内容から記事案を重複生成しない
- slugは英小文字・数字・ハイフンのみ
- 新規記事は同名ファイルを上書きしない
- Astro build失敗時は公開しない
- GitHubへのpush成功後だけNotionを`公開済`にする

## 必要なGitHub Actions Secrets

| Secret | 内容 |
|---|---|
| `NOTION_TOKEN` | 共通記事DB、会議ログ、判断ライブラリへアクセスできるNotion Integration token |
| `OPENAI_API_KEY` | 記事案生成・変更判定に使用するAPI key |
| `NOTION_ARTICLE_DRAFT_DATA_SOURCE_ID` | 共通記事DBのdata source ID |
| `NOTION_MEETING_LOG_DATA_SOURCE_ID` | 会議・相談ログのdata source ID |
| `NOTION_JUDGMENT_LIBRARY_DATA_SOURCE_ID` | 判断ライブラリのdata source ID |

任意のRepository Variable:

- `OPENAI_MODEL`
